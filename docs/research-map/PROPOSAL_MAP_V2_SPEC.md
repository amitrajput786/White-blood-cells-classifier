# Proposal Map v2: build spec

**What this file is.** A build instruction for an agent (or for you) to turn the current
*WBC-DG Proposal Map* artifact into a learning tool that takes you from reading, through
understanding and a TL;DR, to a written proposal. Version 2 borrows the learning method of
[amosblomqvist/learnharness](https://github.com/amosblomqvist/learnharness) (v0.4.0).

- **Current map (v1):** https://claude.ai/artifact/2dV4ozTZ6qtzf3KKYjkJbR. It is a single HTML
  file with 8 tabbed stages, checkboxes, and notes saved to `localStorage`.
- **Source of the method:** learnharness `docs/teaching-methodology.md`, `docs/vision.md`,
  `docs/probe-teach-split.md`, and `src/agent/prompts/{prober,teacher,practice,shared}/*.md`.
- **Licence note:** learnharness is AGPL-3.0. Reuse its *ideas* and restate its doctrine in
  your own words. Do **not** paste its code or prompt text into the artifact.

## Part 1. What learnharness is

### TL;DR

LearnHarness is an Electron/Next.js app in which LLM agents teach you. Before teaching, they
**measure** what you already understand. They then **plan** the smallest dependency tree from
there to your goal, and **teach** it one reasoning step at a time, checking each step before
moving on. Later, separate **practice** sessions make the knowledge come to mind when you need
it. Everything you learn is stored in a persistent **knowledge graph** made of propositions
and reasoning chains, and each item links back to the exact moment it came up.

### The theory, in seven claims

These come from `docs/teaching-methodology.md` and `teacher/05-method.md`:

1. **Two states.** Every session runs from *current understanding* (what you already hold as
   obviously true) to *goal understanding*. The probe has to pin down both precisely.
2. **You have learned something when it feels obviously true.** Being able to recite it, or
   having covered it, does not count. Facts you only memorize fade; facts you understand stay.
3. **The click.** Loose facts ("that's just how it is") collapse into a structure generated by
   a few base facts. You know *why*, not just *that*.
4. **Knowledge is a graph.** Propositions are nodes. Edges are `follows` (B can be derived
   from A) or `supports` (A justifies B without implying it). A *chain* is a set of premises
   that **jointly** imply a conclusion: `A ∧ B ⟹ C`.
5. **Teaching means stating facts in order, one reasoning step at a time.** Each step starts
   from something you already hold, so it lands as self-evident, and a mistake shows up
   immediately and in a known place.
6. **Foundations first (Principle i), then motivated derivation (Principle ii).** Start from
   *unconditional truths*, meaning facts you can accept as they are, with no caveats. For
   everything after that, show "how could I have discovered this?"
7. **Two separate optimizations.** (a) Put your effort into the material, and let the system
   absorb the logistics: what to read, in what order, and fact-checking. (b) Plan the
   **minimal tree**: don't re-teach anything you already hold, and teach nothing off the path
   to the goal.

### The machinery that implements it

| Mechanism | Where | What it does |
|---|---|---|
| **Probe** | `prober/10-probe-doctrine.md`, `contracts/probe.ts` | Makes the goal concrete. Breaks it into *strands* (the dependencies) and finds your edge on each one by **binary search**, bracketing between a *floor* you reliably get right and a *ceiling* you miss. Ends with `probe_done`, which records each strand with its floor, ceiling, misconceptions and where to build from. |
| **Plan map** | `teacher/10-planning.md` | A live dependency DAG. Its nodes are landmarks: unconditional truths at the bottom, the goal at the top. It is a *map, not a syllabus*, and it gets rewritten whenever teaching shows that the plan was wrong about you. |
| **Predict → teach → check** | `teacher/28-predictions.md`, `30-question-principles.md` | Each step opens with a *prediction*, an attempt at the step before it is taught. A *check* comes after, kept collapsed until you choose to open it. A good check asks you to apply the idea, never to repeat it back, and each wrong option points to a specific wrong model. |
| **Confidence** | `shared/25-confidence.md`, `components/confidence-rail.tsx` | Every answer carries a confidence value (stops at 0/30/50/70/90/100). A wrong answer given with high confidence is the strongest signal there is: it means a committed misconception. A right answer given with low confidence means the knowledge is fragile. "I don't know" counts as an honest gap, not as a wrong answer. |
| **Thinking fields** | `shared/16-mental-model.md` | Every question has a free-text field where you think out loud. It is treated as the *primary data*: "one answer is one bit; the thinking is the picture." |
| **Practice** | `practice/10-doctrine.md` | A separate mode for questions asked *when the idea is not fresh in your mind* (*inactive*). It has three modes: **recall**, then **discrimination** (choosing between near-twins), then **composition** (running a whole chain). It interleaves targets, aims for about 85% success per retrieval, uses a hint ladder R0–R5 that gives one rung per request, classifies each miss, and **retests every miss on a new problem before the session ends**. |
| **Knowledge graph** | `docs/vision.md` §1, `contracts/graph.ts`, `chain-table.tsx` | Propositions have a short `name`, a precise `statement` and `aliases`. Chains are drawn as `A ∧ B ⟹ C`. Each item has message-level *provenance*. Clusters are detected from the edges (Louvain). Understanding is **inferred from evidence and never stored as a "done" flag**: there is no `taught` event. |
| **Notes import** | `vision.md` "format-agnostic front door" | The same extraction pipeline runs over your own notes and turns them into propositions and chains. |
| **Jobs** | `teacher/40-jobs.md`, `50-demos.md` | Fact-checking, PDF reading, demos and figures run in the background while teaching continues. |

## Part 2. Your v1 map compared with learnharness

### What v1 already does well (keep it)

- A clear linear route with a stated *golden thread*: Problem → Gap → Question → Hypotheses →
  Method → Evaluation → Outcome → Plan. This is a chain. v2 should make it a real one.
- "Write first, then open the hint" is a prediction in all but name.
- The writing order differs from the reading order, and the core sections come first. This
  is close to minimal-tree thinking.
- The content is excellent: 10 papers with targeted questions, 3 pilots, Prof. Mitra's 5
  points, 13 proposal sections, a LaTeX skeleton, an interview bank and a whiteboard set.
  **All of it carries over.**

### Gaps, ranked by how much fixing each one improves learning

| # | v1 behaviour | Learnharness principle it misses | v2 fix |
|---|---|---|---|
| 1 | Progress means **ticked checkboxes**. | There is no `taught` event, so understanding has to be inferred from evidence. A tick only shows that something was done. | Every node's state is derived from its **checks** (verdict, confidence and thinking). A tick can mark work done, but it never marks a node as understood. |
| 2 | Everyone reads all 10 papers in the same order. | **Probe first, then the minimal tree.** Don't re-teach what you already hold. | A 10–15 minute **probe** with strands such as DG vs DA, acquisition vs manifestation shift, DomainBed model selection, BatchNorm under shift, stain normalization vs augmentation, macro-F1 vs accuracy and the WBC dataset caveats. Its result marks some readings as *skip / skim / deep*. |
| 3 | The stages are a **linear tab row**. | **Plan map as a DAG.** Pilot 3 feeds Point 4, which feeds §8 Method; Castro feeds Point 4; DomainBed feeds Point 5 and §9. | A **dependency map** view in which each stage, paper, pilot, point and section is a node with real `requires` edges. The "where you are" marker comes from what you most recently engaged with. |
| 4 | "Extract these answers" are **recall prompts** with no grading. | **Predict → check** with applied questions whose wrong options each name a wrong model. | Each paper gets one **prediction** before reading ("Will GroupNorm help Raabin→LISC? By how much?") and two or three **checks** afterwards: multiple choice with diagnostic distractors, plus confidence and a thinking field. |
| 5 | No confidence values and no thinking fields. | Wrong + high confidence means a misconception, and thinking is the primary data. | A confidence rail (0/30/50/70/90/100) and a thinking textarea on every check. A **calibration panel** shows confidence plotted against correctness. |
| 6 | Reading cards and the literature matrix are separate free text. | **Propositions and chains with provenance.** | Each reading produces 2–5 **propositions** (`name`, `statement`, source = paper and page). The literature matrix becomes a *view* over them. The gap statement becomes a **chain**: `P_tsutsui ∧ P_sada ∧ P_jahanifar ⟹ GAP`. |
| 7 | No step between "understood" and "write". | **The click**, where loose facts collapse into generators. | A new **TL;DR stage**: compress everything into 3–5 *unconditional truths* plus the chain to your RQ. If the RQ doesn't follow from them, the gap is in your understanding, not in your writing. |
| 8 | Interview practice is a list of questions you answer aloud. | **Practice doctrine**: recall → discrimination → composition, interleaving, hint ladder, retest on a new problem. | A **Practice** mode that draws problems from your propositions and chains, interleaves them, uses hints R0–R5 and retests misses before closing. The interview bank and whiteboard set become this mode's material. |
| 9 | Proposal sections list what they need from your material, but nothing checks it. | Golden thread = chains. Every claim must trace back. | Each § card lists the **chains it must state**. A **thread checker** flags any method block or experiment that isn't premised in a sub-question chain, and any claim with no provenance. |
| 10 | Notes live only in `localStorage`, with one "copy notes" button. | Plain, inspectable files you own. | **Export and import JSON**, plus Markdown export of the TL;DR, chains and answers. Use the artifact's durable storage capability if the builder has it, with `localStorage` only as a fallback. |

### What NOT to copy

- The LLM teacher, prober and extraction agents, the Electron shell, provider keys and
  dictation. v2 is a **single self-contained HTML artifact** with no backend.
- Graph libraries meant for thousands of nodes (sigma.js, Louvain). Your graph will have
  about 60–120 nodes, so a small SVG with a fixed layered layout is enough.
- Learnharness's rule that "the system absorbs logistics" does **not** mean the map writes
  your proposal. Keep v1's rule: *every sentence of the proposal stays yours.* The map handles
  ordering, structure and checking. You write the content.
- Optional exception: if the builder has the artifact capability for asking Claude a
  question, it **may** add a "grade my free-recall answer" button. It must sit behind a
  toggle, and the default is self-grading against a revealed model answer.

## Part 3. The v2 build spec

### 3.1 Learning flow (it replaces the 8 linear stages but keeps their content)

```
0 Orient ──▶ 1 Probe ──▶ 2 Plan map ──▶ 3 Learn (read + pilot, per node: predict → read/run → check)
                                              │
                                              ▼
                     4 Five answers ──▶ 5 TL;DR (the click) ──▶ 6 Write (section by section, chain-checked)
                                                                       │
                                                                       ▼
                                                  7 Review & send ──▶ 8 Practice (interview, interleaved, retests)
```

Movement is **not locked**: you can open any node. The map shows each node's derived state and
recommends the next node by following the dependency edges.

### 3.2 Data model (one JSON object, versioned)

```ts
type State = {
  version: 2;
  goal: { decision: string; rq: string; subq: { id: string; q: string; h: string }[] };
  probe: { strands: Strand[]; done: boolean };
  nodes: Record<string, Node>;           // static content, shipped in the file (see 3.6)
  props: Record<string, Proposition>;    // you author these as you learn
  chains: Record<string, Chain>;
  answers: Record<string, Answer[]>;     // keyed by question id; append-only history
  notes: Record<string, string>;         // v1 note ids are preserved: decision, a1..a5, rq, subq
  work: Record<string, boolean>;         // v1 checkbox ids are preserved, relabelled as "work done"
  practice: { log: PracticeEvent[] };
};

type Strand = { id: string; name: string; floor?: string; ceiling?: string;
                misconceptions: string[]; verdict: "held" | "shaky" | "missing" };

type Node = { id: string; kind: "stage"|"paper"|"pilot"|"point"|"section"|"concept";
              title: string; requires: string[];      // DAG edges
              strands: string[];                      // which probe strands it serves
              questions: Question[]; body: string };  // body = v1 card HTML/markdown

type Question = { id: string; role: "predict"|"check";
                  stem: string; options?: string[]; correct?: number;
                  explanation: string;                 // written before correct; shown after answering
                  distractorModels?: string[] };       // the wrong model each option represents

type Answer = { at: string; pick?: number; text?: string; dontKnow?: boolean;
                confidence?: 0|30|50|70|90|100; thinking: string; selfGrade?: "right"|"partial"|"wrong" };

type Proposition = { id: string; name: string;        // ≤ 5 words, glossary-style handle
                     statement: string;               // full precision, one claim
                     source: { node: string; ref?: string }[];  // paper + page / pilot run
                     kind?: "unconditional" | "derived" };
type Chain = { id: string; premises: string[]; conclusion: string;
               relation: "follows" | "supports"; usedIn: string[] };  // section ids that state it

type PracticeEvent = { at: string; target: string; mode: "recall"|"discrimination"|"composition";
                       hintRung: 0|1|2|3|4|5; outcome: "solved"|"missed"|"surrendered";
                       miss?: "cue"|"discrimination"|"execution"|"careless"|"structural"; retestOf?: string };
```

**Derived node state** is computed on read and never stored:

- `not started`: no answers yet.
- `shaky`: any check missed, or right but with confidence ≤ 50.
- `misconception`: any check wrong with confidence ≥ 70. Show this one prominently.
- `held`: every check right with confidence ≥ 70, and the most recent attempt was not a miss.

### 3.3 Views

1. **Map:** an SVG DAG laid out in layers (foundations at the bottom, the proposal at the top).
   Each node is coloured by derived state, using v1's Giemsa palette: azure for your path, eosin
   for misconceptions and traps, green for held. Clicking a node opens it. A **Next** button
   picks the lowest node whose `requires` are all `held` and which is not held itself. Probe
   results draw *skip* nodes faded.
2. **Node page:** the v1 card content, with **predict** above the body (open, answered first)
   and **checks** below the body, collapsed behind "Check your understanding". Each question
   has a confidence rail and a thinking field. A "+ Proposition" button sits beside every
   paragraph and pilot result.
3. **Probe:** a short sequence of questions, one per turn, ordered by binary search within each
   strand. It enters near the top of the strand: a confident right answer jumps up, and a miss
   steps down. It produces the strand table and the skip/skim/deep marks on paper nodes.
4. **Argument:** a table of all chains rendered as `A ∧ B ⟹ C` with chips. Clicking a chip shows
   the statement and its provenance. It also holds the **thread checker** (3.5).
5. **TL;DR:** a fixed form with five slots:
   - *Unconditional truths* (3–5 propositions marked `unconditional`)
   - *The failure* (one proposition with your number)
   - *The gap* (a chain)
   - *The question* (RQ, plus the sub-questions with hypotheses that can be falsified)
   - *Why this answers Prof. Mitra* (each of the 5 points mapped to a proposition or chain)

   The stage is complete only when every RQ sub-question is the conclusion of a chain whose
   premises are props marked held.
6. **Write:** the v1 §-cards in writing order. Each card shows the chains it must state, with a
   ✓ once a chain is linked through `usedIn`. Keep the v1 LaTeX skeleton and its copy button.
7. **Practice:** draws problems from held props and chains, plus the v1 interview bank and
   whiteboard set. It follows the doctrine in 3.4.
8. **Evidence:** a calibration plot (confidence bucket against % correct), a list of
   misconceptions, every answer with its thinking in date order, and the practice log.

### 3.4 Practice rules (a short version of the practice doctrine)

- Pick the target in this order: weakest first, then the one feeding the most chains, then the
  least recently used. Pick the mode as the cheapest one this target has not yet shown:
  recall, then discrimination, then composition.
- **Never** give two problems on the same target in a row; interleave.
- Hints come one rung per click: R0 re-read the givens, R1 name the pattern, R2 name the
  candidate class, R3 name the proposition, R4 outline the move, R5 the worked step. Log the
  rung used, since it measures difficulty.
- After a miss, classify it: cue, discrimination, execution, careless or structural.
  Structural means a misconception, so link back to the node page.
- **Before the session ends, retest every miss and every problem that needed hint R3 or above,
  using a different question (a fresh surface).**
- Discrimination problems for your topic include: DG vs test-time adaptation (AdaBN),
  acquisition vs manifestation shift, Reinhard vs HED augmentation, macro-F1 vs accuracy, and
  in-distribution vs out-of-distribution numbers.

### 3.5 Thread checker (the golden thread, made mechanical)

It flags any of the following:

- A sub-question with no hypothesis, or a hypothesis that can't fail (you confirm this by hand
  with a checkbox).
- A §8 Method block whose `usedIn` chain doesn't conclude in a sub-question.
- A §10 result proposition with no pilot node in its `source`.
- Any proposition used in §5 or §3 with no paper in its `source`.
- Any of Prof. Mitra's 5 points with no linked chain.
- Any number in a proposition that is not labelled ID or OOD (a regex for `%` or `F1`, plus a
  required tag).

### 3.6 Content migration from v1 (nothing is lost)

| v1 | v2 |
|---|---|
| `STAGES` (0–7) | `stage` nodes; the order becomes `requires` edges |
| `PAPERS_A`, `PAPERS_B` (`why`, `ex[]`) | `paper` nodes; `why` becomes the body; each `ex` item becomes a **check** (rewrite it as an applied question with 4 options whose distractors each name a wrong model); add 1 predict per paper |
| Pilots 1–3 and the results table | `pilot` nodes; each result row becomes a proposition sourced to its run |
| `POINTS` (`q`, `decide[]`, `hint`) | `point` nodes; `decide` items become checks; `hint` stays collapsed and only opens after you write the note |
| `SECTIONS` | `section` nodes with a `chainsRequired` list |
| `LATEX`, review list, email guidance, fortnightly template | kept as they are inside their nodes |
| `QS` (14 interview Qs), whiteboard set | material for the Practice pool |
| `localStorage` key `wbcdg-proposal-map-v1` | on first load, migrate `checks` → `work` and `notes` → `notes`, then save as v2 |

Concept nodes to add, each the bottom of a strand: `dg-vs-da`, `acq-vs-manifest`,
`model-selection`, `bn-stats-shift`, `stain-norm-vs-aug`, `macro-f1`,
`id-vs-ood`, `class-conditional-shift`.

### 3.7 Technical constraints

- One self-contained `.html` file with vanilla JS, as in v1. React is optional. Use no build
  step and no external JS beyond pinned CDN versions.
- Keep v1's design tokens (the Giemsa palette, Bricolage / Source Serif / JetBrains Mono), light
  and dark mode, and a mobile layout with a 16px gutter and no horizontal scroll.
- Wrap all storage calls in try/catch. The page must render with storage unavailable.
- **Export JSON / Import JSON / Export TL;DR+chains as Markdown**, so your record can leave the
  browser.
- Accessibility: every control has a label, focus is visible, and the confidence rail works
  from the keyboard (arrow keys move between stops).

### 3.8 Acceptance criteria

1. Loading v2 with existing v1 data keeps every note and tick.
2. The probe marks at least one paper *skip* when you answer its strand correctly with ≥ 90
   confidence.
3. A wrong answer with confidence ≥ 70 turns that node eosin on the Map and lists it under
   Evidence → Misconceptions.
4. No node can show *held* from checkbox ticks alone.
5. TL;DR stays incomplete until every sub-question is the conclusion of a chain.
6. Practice never serves the same target twice in a row, and the session-end screen lists any
   misses that have not been retested.
7. The thread checker reports 0 issues on a deliberately complete sample state and flags at
   least one issue on the empty state.
8. Export → clear storage → Import restores the identical state.

### 3.9 Build order

1. Data model, v1 migration, export and import.
2. Node page with predict/check, confidence and thinking (most of the value is here).
3. Map view with derived states and **Next**.
4. Propositions, chains and the Argument view.
5. TL;DR stage.
6. Write view with the thread checker.
7. Probe.
8. Practice and Evidence.

## Part 4. How to use v2 for this proposal

1. **Probe (15 min).** Be honest with your confidence. This decides which of the 10 papers you
   read deeply.
2. **Learn.** For each node on the map: predict, then read or run it, then check, then add 2–5
   propositions. A miss sends you back into the node, not forward.
3. **Five answers.** Write each one in your own words, then open the hint. Turn each answer
   into a chain.
4. **TL;DR.** If you can't state the RQ as the conclusion of your held propositions, you don't
   have a writing problem yet. Go back to the node that is shaky.
5. **Write.** Each § states the chains it lists. Run the thread checker before you send the
   draft to Prof. Ari.
6. **Practice** the interview from your own graph: interleave, use the hint ladder, retest.
